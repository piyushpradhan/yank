# Sensitive copies

Yank checks copies before retaining them in clipboard history. **Block sensitive copies** defaults to on and is available in **Tweaks → Privacy** and **Tweaks → shield icon → Privacy & usage**. The setting is saved on this device and takes effect without restarting. It is independent of usage sharing and AI settings.

Turning it off saves sensitive copies like any other clip: both source retention markers and text detection are ignored. Builds before 0.7.75 stored a text-detection-only preference; it is not carried over, so the broader setting starts blocked after upgrading.

This leaves the system clipboard alone: normal paste continues to work. It does not delete or rescan existing history, labels, or embeddings.

## Excluded when blocking is on: source retention markers

These checks run before reading text or images:

| Platform | Markers that cause Yank to skip a copy |
| --- | --- |
| macOS | `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`; compatibility markers `com.agilebits.onepassword`, `net.antelle.keeweb`, `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping`, and `Pasteboard generator type` |
| Windows | Presence of `ExcludeClipboardContentFromMonitorProcessing` or `Clipboard Viewer Ignore`; a zero DWORD in `CanIncludeInClipboardHistory` or `CanUploadToCloudClipboard` |
| Linux / X11 and Wayland | Presence of the `x-kde-passwordManagerHint` selection target or offer MIME type, including when its value cannot be served |

Transient and auto-generated markers describe retention policy, not necessarily secret content. Honoring `CanUploadToCloudClipboard = 0` as a local-history exclusion is a conservative Yank policy; Windows itself defines that flag only as a cloud-sync opt-out.

On macOS, Windows, and X11, Yank checks metadata again after reading a payload and discards it if the clipboard generation changed or became marked. Failed or inconsistent metadata inspections skip the capture attempt and retry on a later poll; they do not fall back to saving unchecked content. Rejected content is not cached for deduplication or included in diagnostic messages.

On native Wayland, Yank uses ext-data-control or wlr-data-control when available. It checks metadata and requests plain text and PNG from the same immutable offer, so changing the selection between reads cannot substitute unchecked content. A small vendored wl-clipboard-rs patch also guards arboard reads; those always reject marked offers, while the watcher's snapshot read accepts them when blocking is off. Compositors without data-control support fall back to X11/XWayland, where XFixes change notifications and a bounded selection-target inspection protect captures. A bridge or intermediary may omit original markers; native Wayland support is not universal. Native Wayland PNG transfers are capped at 200 MB compressed and 50 million pixels.

## Excluded when blocking is on: text detection

All detection is local and deterministic. A match rejects the **entire clip** before category/preview generation, SQLite insertion or deduplication updates, FTS indexing, UI events, and label/embedding queue notifications. No classifier service or credential-verification API is called.

| Kind | Implemented rule |
| --- | --- |
| Card-like numbers | 13–19 digits, Luhn checksum, and supported grouping: compact; groups of four with a final group of 1–4 digits; or `4–6–4/5` grouping. All-identical digit runs are rejected as card candidates. There is no hardcoded issuer-prefix gate, so Mastercard 2-series and 19-digit candidates are covered |
| US Social Security numbers | Structurally plausible `3–2–4` grouping with spaces, dots, or hyphens. Bare nine-digit numbers require an `SSN` or `social security` label within 64 bytes before/after. Areas `000`, `666`, `900–999`, group `00`, and serial `0000` are rejected as SSN candidates |
| Labeled credentials | Nonempty values assigned with `:` or `=` to `password`, `passwd`, `pwd`, `passphrase`, `client_secret`, `api_key`, `access_token`, `refresh_token`, `auth_token`, `secret_key`, `secret`, or `token`. Matching is case-insensitive; compound names also accept a hyphen or no separator. Quoted JSON/YAML-style names and values are supported, including weak passwords |
| HTTP credentials | `Authorization:` or `Proxy-Authorization:` with a Basic/Bearer value; URL user-info containing both a username and password |
| Recognizable token patterns | GitHub legacy `gh[pousr]_` plus 36 alphanumeric characters; `github_pat_` plus at least 60 token characters; Stripe-like `sk_`/`rk_` live/test values with at least 16 alphanumeric characters; `sk-` values with optional `proj-`/`svcacct-` and at least 20 token characters; Slack-like `xox[baprs]-` values with at least 20 token characters. These are shape checks, not proof that a credential is active |
| Private-key headers | PEM-style `BEGIN PRIVATE KEY`, including RSA, EC, DSA, OPENSSH, and ENCRYPTED variants. Incomplete copies containing the header are also excluded; public-key headers alone are retained |
| Scan budget | Text larger than **1 MiB of UTF-8 bytes** is skipped rather than saving a partially checked clip |

Numeric detection normalizes nonbreaking/figure/narrow-nonbreaking spaces, common Unicode dashes/minus signs, and full-width digits. It scans the complete retained text within the budget. It does not concatenate digits across lines or words, or accept a substring inside a longer uninterrupted number. Adjacent numeric fields can still be ambiguous; supported grouping deliberately limits concatenation.

Public example/test card and SSN values are not generally allowlisted: they can be used to test the setting. No real secrets are needed for tests.

## Limits and decisions

- An absent marker is not evidence that a copy is safe. Producer apps, browser extensions, copy buttons, selection-copy shortcuts, clipboard bridges, and intermediaries differ in whether they supply markers.
- An arbitrary standalone password, passphrase, PIN, OTP, or CVV may look exactly like ordinary text or a number. These are not universally detected. Entropy and password-strength scores are not used as a blanket filter.
- Luhn and SSN structural checks validate a pattern, not an issued card or identity. Ordinary IDs may match, and unsupported/partial formats may be missed.
- Unmarked images/screenshots are not inspected with OCR. Source markers still exclude marked images and mixed-format copies. When an image also offers text, that text is checked before retaining the image.
- Emails, phone numbers, postal addresses, ordinary unlabelled numeric IDs, and public keys remain useful clipboard content and are retained unless another rule matches. IBANs, other national IDs, wallet seed phrases, and arbitrary unlabeled tokens do not have dedicated rules in this version.
- This setting covers newly observed OS clipboard copies. Manually editing an existing history item is an explicit save and is not filtered. Previously saved items can still be processed by configured AI features; enabling this setting does not retroactively protect them.
- There is no rejected-content queue, cloud classification, online credential verification, app-exclusion list, or strict-mode policy in this implementation. The first version uses the reviewed rules above and source markers.

The capture settings lock is held through persistence, so turning protection on waits for writes already using the old policy. Metadata is evaluated per clipboard generation, before content deduplication. Native generation checks reduce races; they cannot compensate for a producer that marks content only after it has already published an unmarked copy.

The implementation is in `src-tauri/src/sensitive.rs`, `clipboard_privacy.rs`, `clipboard_privacy_x11.rs`, `clipboard_privacy_wayland.rs`, and `watcher.rs`. Regression checks cover synthetic text boundaries, private macOS pasteboard markers, replacement/marker races, history/FTS exclusion, existing-row deduplication, and the settings UI. No universal accuracy percentage is claimed. The earlier [research/design](research/sensitive-clipboard-detection.md) and [scanner audit](research/sensitive-data-scanners.md) explain the alternatives and source evidence; this document is the implemented policy.
