A background worker owns the clipboard

move gives the thread what it needs.

The closure takes ownership of the app handle, then loops forever. Each pass sleeps, checks images first, and falls back to text.

move closure ownership Option<T> match
Why no async task here?

arboard is synchronous. A dedicated OS thread keeps blocking clipboard work away from the UI and async runtime.

src-tauri/src/watcher.rs Rust, selected lines 
pub fn spawn(app: AppHandle) {
    std::thread::spawn(move || {
        let mut cb = match Clipboard::new() {
            Ok(c) => c,
            Err(err) => {
                eprintln!("[watcher] clipboard init failed: {err}");
                return;
            }
        };
        let mut last_text: Option<String> = None;
        let mut last_image_hash: Option<u64> = None;
        loop {
            std::thread::sleep(Duration::from_millis(500));

            if let Ok(img) = cb.get_image() {
                let hash = image_hash(&img);
                if last_image_hash != Some(hash) {
                    last_image_hash = Some(hash);
                    let source = active_window_title();
                    insert_image_and_emit(&app, &img, source);
                }
                continue;
            }

            // Check for text
            let text = match cb.get_text() {
                Ok(t) => t,
                Err(_) => continue,
            };
            if last_text.as_deref() == Some(text.as_str()) {
                continue;
            }
            last_text = Some(text.clone());
            insert_text_and_emit(&app, &text, active_window_title());
        }
    });
}
Cheap rules run before expensive AI

Early returns make the decision tree readable.

A borrowed &str enters. A static category label leaves. Nothing is allocated for the result, and the first confident rule wins.

&str borrowing &'static str iterators early return
Order is product behavior

Number detection runs before phone detection, while color detection runs before both. Moving a branch can change user-visible categories.

src-tauri/src/categorize.rs Rust, selected lines 
pub fn categorize(text: &str) -> &'static str {
    let trimmed = text.trim();
    if trimmed.is_empty() {
        return "text";
    }
    let single_line = !trimmed.contains('\n');

    if single_line {
        if RE_URL.is_match(trimmed) {
            return "url";
        }
        if RE_EMAIL.is_match(trimmed) {
            return "email";
        }
        if RE_HEX.is_match(trimmed)
            || RE_RGB.is_match(trimmed)
            || color_names::is_named_color(trimmed)
        {
            return "color";
        }
        if RE_NUMBER.is_match(trimmed) {
            return "number";
        }
        if RE_PHONE.is_match(trimmed) {
            let digits = trimmed.chars().filter(|c| c.is_ascii_digit()).count();
            if digits >= 7 && digits <= 15 {
                return "phone";
            }
        }
    }

    let lines = trimmed.lines().count();
    if lines >= 3 && RE_CODEY.is_match(trimmed) {
        return "code";
    }
    "text"
}
Shared state has one synchronized door

Arc<Db> shares. Mutex protects.

Tauri commands and workers all need the same SQLite connection. Arc provides shared ownership; Mutex permits one connection user at a time.

Arc<T> Mutex<T> Result<T, E> ? operator
The lock stays small

Yank releases the database guard before kicking background work. Long network or embedding work never happens while SQLite is locked.

src-tauri/src/watcher.rs Rust, selected lines 
fn insert_text_and_emit(app: &AppHandle, text: &str, source: Option<String>) {
    let category = categorize(text);
    let preview = make_preview(text);
    let db: Arc<Db> = app.state::<Arc<Db>>().inner().clone();
    let id = {
        let conn = db.0.lock().unwrap();

        match crate::db::dedup_text(&conn, text) {
            Ok(Some(existing_id)) => {
                let now = chrono::Utc::now().timestamp_millis();
                let _ = conn.execute(
                    "UPDATE items SET last_used_at = ?1 WHERE id = ?2",
                    rusqlite::params![now, existing_id],
                );
                existing_id
            }
            Ok(None) => match crate::db::insert_item(
                &conn,
                text,
                category,
                &preview,
                source.as_deref(),
            ) {
                Ok(id) => id,
                Err(err) => {
                    eprintln!("[watcher] insert failed: {err}");
                    return;
                }
            },
            Err(err) => {
                eprintln!("[watcher] dedup check failed: {err}");
                return;
            }
        }
    };
    let _ = app.emit("clip-added", id);
    crate::label_queue::kick(app);
    crate::embed_queue::kick(app);
}

#[tauri::command]
pub fn list_items(db: State<'_, Arc<Db>>) -> Result<Vec<ClipItem>, String> {
    let conn = db.0.lock().map_err(|e| e.to_string())?;
    let mut stmt = conn.prepare(
        "SELECT id, content, category, label, preview, source,
                pinned, deleted, deleted_at, last_used_at
         FROM items
         WHERE deleted = 0
         ORDER BY pinned DESC, last_used_at DESC
         LIMIT 500",
    ).map_err(map_err)?;
    let rows = stmt
        .query_map([], row_to_item)
        .map_err(map_err)?
        .collect::<rusqlite::Result<Vec<_>>>()
        .map_err(map_err)?;
    Ok(rows)
}

Decode the Rust you keep seeing.

These patterns recur across Yank. Learn their job here, then return to the trace and read the same lines with less friction.

Borrow data without taking it.

&T gives temporary read access. The caller remains the owner, so the same value can be reused after the function returns.

pub fn categorize(text: &str) -> &'static str let category = categorize(text); let preview = make_preview(text);

Plain English: “Let me read this string. I will not keep it or destroy it.”

Absence is part of the type.

Option<T> is either Some(value) or None. Yank uses it for source titles, time windows, and values that may not exist.

let mut last_text: Option<String> = None; if last_text.as_deref() == Some(text.as_str()) { continue; }

Plain English: “There may be a previous clip. If there is, compare its string view.”

Failure travels through normal control flow.

Result<T, E> forces success and failure to be handled. The ? operator returns early on error and unwraps the success value.

pub fn open(path: &Path) -> rusqlite::Result<Connection> { let conn = Connection::open(path)?; migrate(&conn)?; Ok(conn) }

Plain English: “Open, then migrate. If either fails, stop and return that error.”

Share ownership, serialize access.

Arc keeps shared data alive across threads. Mutex makes each user acquire a guard before touching SQLite.

pub struct Db(pub Mutex<Connection>); let db = Arc::new(Db(Mutex::new(conn))); app.manage(db.clone()); let conn = db.0.lock()?;

Plain English: “Many tasks may hold the database handle, but only one enters the connection at a time.”

Move captured values into the new thread.

A spawned thread can outlive its caller. move transfers the closure's captured values so their lifetime is no longer tied to the current stack frame.

pub fn spawn(app: AppHandle) { std::thread::spawn(move || { // this thread now owns its AppHandle insert_text_and_emit(&app, &text, source); }); }

Plain English: “Thread, take your own app handle. Do not borrow mine.”

Compile only the code this platform needs.

Conditional compilation removes irrelevant branches from the binary. Yank uses it for native window focus, paste keystrokes, and active-window metadata.

#[cfg(target_os = "macos")] fn send_paste_keystroke() -> Result<(), String> { ... } #[cfg(not(target_os = "macos"))] fn send_paste_keystroke() -> Result<(), String> { ... }

Plain English: “Build exactly one implementation for the current operating system.”

Make the branches move.

These browser labs mirror the order of Yank's Rust logic. They are learning aids; the Rust source remains the authority.

Watch the first matching branch win. This is why the order in categorize.rs is part of Yank's product behavior.
