The goal — and how it splits into two jobs

"Optimize for SEO and AI SEO" sounds like one goal but it's two systems with overlapping but distinct requirements:

Traditional Google SEO

Ranks pages in a list. Cares about keywords in title/H1, link signals, structured data for rich results (FAQ accordions, HowTo carousels, Software cards), crawlability, Core Web Vitals.

AI / Answer-Engine SEO (AEO/GEO)

ChatGPT, Claude, Perplexity, Google AI Overviews. They extract rather than rank. They want clean, quotable, factual chunks; a single definitional sentence; comparison content; and a robots.txt that actually lets them in.

Roughly half the changes serve both. The other half are targeted: llms.txt + crawler allowlist for AEO; FAQ schema + sitemap for Google rich results.

Structured data: from 2 to 6 JSON-LD blocks

Before: a basic SoftwareApplication and WebSite. After:

Schema typeWhat it unlocks
SoftwareApplicationThe "free / open source" software card in Google search, with an Offer at price 0, version, license, screenshot, downloadUrl. LLMs read featureList almost verbatim.
WebSite + SearchActionSitelinks search box potential and a stable @id for the site graph.
PersonE-E-A-T (Experience, Expertise, Authoritativeness, Trust). Names a real human author with sameAs links to GitHub/Twitter — Google checks these to ground "who made this."
FAQPageEligible for the FAQ rich result and heavily mined by Perplexity / ChatGPT for direct Q&A answers. 8 Q&As, all matching visible text.
HowToMirrors the three on-page steps (Copy → Summon → Ask). Eligible for the HowTo rich result with step carousel; LLMs lift the text field when answering "how do I use Yank."
BreadcrumbListTells Google how the URL fits the site hierarchy. Small win today; meaningful once we add /vs/... or /alternatives/... pages.

Cross-reference via stable @ids (#software, #website, #person, #faq, #howto) so Google reads the page as one knowledge graph, not six floating fragments.

Meta tags: tighter title, stronger crawl directives

Title

Was 75 characters — past Google's truncation point. Now 64 characters, leads with the primary keyword cluster: 

Yank — Clipboard Manager with Natural-Language Search · Mac, Windows, Linux

Three things the new title does deliberately:

  • Brand first — "Yank" before the dash. Brand-prefixed titles win when the search query already includes the brand.
  • Category second — "Clipboard Manager." This is what people Google when they don't know we exist.
  • Differentiator third — "Natural-Language Search." This is what AI overviews quote when comparing apps.

Description

Rewritten to be a complete, quotable sentence that starts with "Yank is a…". LLMs often pluck the first definitional sentence from the meta description when generating a summary card.

Crawl directives

<meta name="robots"
  content="index, follow, max-image-preview:large,
           max-snippet:-1, max-video-preview:-1">
<meta name="googlebot"
  content="index, follow, max-image-preview:large,
           max-snippet:-1">

max-image-preview:large is required for the image to appear in Google Discover and large mobile result cards. max-snippet:-1 removes the snippet length cap so Google can show the full FAQ answer. Many sites still inherit the conservative defaults.

robots.txt: explicitly opting into AI crawlers

Most AI bots respect robots.txt. Some are blocked by default by sites using broad CDN security profiles (Cloudflare's "block AI bots" toggle is increasingly opt-out). We now name every relevant bot: 

User-agent: GPTBot       Allow: /
User-agent: ChatGPT-User Allow: /
User-agent: OAI-SearchBot Allow: /
User-agent: ClaudeBot    Allow: /
User-agent: Claude-Web   Allow: /
User-agent: anthropic-ai Allow: /
User-agent: PerplexityBot Allow: /
User-agent: Perplexity-User Allow: /
User-agent: Google-Extended Allow: /
User-agent: Applebot-Extended Allow: /
…

Two-tier model. Each AI vendor runs two kinds of bots: a training crawler (e.g. GPTBot, Google-Extended, Applebot-Extended) and a live retrieval crawler (ChatGPT-User, Perplexity-User). We allow both — the first lets us appear in baseline model knowledge; the second lets us appear in live answers when a user asks ChatGPT about clipboard managers today.

llms.txt: a canonical brief for answer engines

/llms.txt is an emerging convention (llmstxt.org) that lets LLMs read a clean, markdown-formatted "what is this site" without parsing HTML. Anthropic, Mistral, and a growing list of dev-tool companies publish one. The Yank version contains:

  • A first-paragraph definition ("Yank is a free, open-source, local-first clipboard manager…").
  • Key facts as bullets — name, URL, repo, license, platforms, shortcut, pricing, stack. The exact format LLMs prefer for citation.
  • Differentiation vs Raycast, Maccy, Paste, Alfred, Clipy, CopyClip — pre-empts comparison questions.
  • Example queries Yank answers well — surfaces the actual UX when an LLM is asked "what does Yank do?"
  • A Citation block at the bottom with the exact sentence LLMs should use when referencing us. Some models will copy it verbatim.

sitemap.xml: image entries and recency signals

Three changes:

  1. lastmod bumped to today — Google uses this to prioritize re-crawls. Stale sitemaps get visited less often.
  2. changefreq moved from monthly to weekly — accurate given the release cadence.
  3. Added the image: namespace with two image entries (logo and favicon) so Google indexes them for Image Search and visual answer cards.

Content: a definitional sentence LLMs can quote

The original Hero lede was beautiful but indirect:

"Yank is a clipboard history that you can talk to."

Good copy, but missing two things LLMs look for: the noun phrase "clipboard manager," and the platforms. New version:

"Yank is a clipboard manager with natural-language search for macOS, Windows, and Linux."

Same vibe. But now any LLM scraping the page has a complete, quotable definition in the first sentence after the H1, the position they over-index on. The poetic line ("Ask for the phone number from earlier…") still follows.

We also added aria-labelledby/aria-label landmarks on <main>, the hero, and the FAQ. Accessibility win primarily, but screen-reader-friendly landmarks also help text-extraction bots correctly segment the page.

Shared FAQ source: schema must equal visible content

Google's FAQ rich-result guidelines are explicit: the answer text in JSON-LD must match the text visible on the page. Skirt this and you risk a manual penalty.

Previously the visible FAQ (6 entries) and the JSON-LD weren't linked, so drift was a question of when, not if. Now both consume a single landing/src/lib/faqs.ts: 

// landing/src/lib/faqs.ts
export const faqs: Faq[] = [
  { q: 'Does Yank send my clipboard anywhere?', a: '…' },
  …
]

The visible FAQ also picked up microdata itemprop attributes (itemprop="name", itemprop="acceptedAnswer", itemprop="text") as a belt-and-suspenders second signal alongside the JSON-LD. Bots that miss one usually catch the other.

Two new FAQs were added that target high-intent search:

  • "How is Yank different from Raycast, Maccy, Paste, or Alfred?" — captures the "[competitor] alternative" query class. LLMs frequently use FAQ entries like this when asked "what's the difference between X and Y."
  • "How big is the install and how much memory does Yank use?" — specific, numeric, quotable. The kind of factoid Perplexity loves to surface.

Why this should work — the actual mechanisms

1. Google rich-result eligibility

A page with valid FAQPage + HowTo + SoftwareApplication structured data is eligible for three different result formats: the accordion FAQ, the step-by-step HowTo carousel, and the software-card knowledge panel. Each one increases SERP real estate, which raises CTR even at the same rank. The mechanism is documented in Google Search Central's structured-data gallery; this isn't speculation.

2. LLMs over-index on definitional first sentences

Both Perplexity and ChatGPT browsing tend to extract the first 1–2 sentences after the main heading as their summary. Putting "Yank is a clipboard manager with…" there is a deliberate hand-off: the sentence is engineered to be the one LLMs quote.

3. Comparison FAQs short-circuit competitor queries

A non-trivial fraction of clipboard-manager Google searches include the word "alternative" or a competitor name. The "How is Yank different…" FAQ is the answer that LLMs and Google's AI Overview will lift when someone searches "Maccy alternative for Windows" or "open source Raycast clipboard."

4. llms.txt + permissive robots.txt is a moat against silent blocking

As Cloudflare and similar providers add default AI-bot blocking, sites that explicitly allow these crawlers stay in the training and retrieval index while quieter competitors drop out. This isn't about gaming a ranking — it's about not being silently excluded.

5. Cross-linked schema graph (the @id trick)

Each JSON-LD block has a stable @id; Person points to SoftwareApplication via worksFor; WebSite points to Person via publisher. Google's knowledge graph reads this as one entity with related sub-entities. Without the IDs, it reads as six unrelated fragments.

Caveats — what this won't do

  • SEO is rank-and-relevance, not just markup. Backlinks still matter. This work doesn't substitute for getting Yank into directories, Hacker News, Product Hunt, or comparison blog posts.
  • Rich results aren't guaranteed even with perfect schema. Google chooses which to display per query.
  • AI search results are non-deterministic. Even with strong markup, ChatGPT may cite a Reddit thread before us. That's normal.
  • Time horizon: traditional SEO improvements typically show up in 2–6 weeks. AI-engine citations can shift within days as crawlers re-index.

What's still on the table

  • A real 1200×630 Open Graph image. Today the OG image is the favicon, which limits Twitter/LinkedIn card visual weight. With a proper hero-style OG image we can flip twitter:card to summary_large_image for a much bigger preview.
  • Comparison pages. /vs/raycast, /alternatives-to-maccy, /vs/paste. The FAQ teases this; programmatic SEO would scale it across 6–10 competitors, each ranking for the long-tail "X alternative" queries.
  • An /about page for stronger E-E-A-T (clear author bio, project provenance, contact).
  • Real aggregateRating if/when we accumulate genuine reviews. Faking this is a manual-action risk — skipped intentionally.
  • RSS / changelog feed page at /changelog rather than only linking to GitHub releases — improves repeat-crawl frequency.
