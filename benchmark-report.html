Yank · Semantic Search: Jev re-ranking vs local embeddings

Fair head-to-head on an identical, paraphrase-heavy query set — 136 seeded items, 56 queries (11 keyword / 45 paraphrase, no shared word stems). Generated 2026-09-20.

Jev re-ranking is not a drop-in replacement for embeddings — it's ~9× worse on paraphrase search. On the semantic subset (the 80% of queries where the user paraphrases instead of reusing words), local embeddings reach P@1 = 0.778; Jev reaches P@1 = 0.089, barely above the BM25 baseline (0.067). Jev can only re-order a BM25 shortlist, and that shortlist almost never contains the right answer when there's no keyword overlap.

Retrieval accuracy by strategy

P@1 = fraction of queries where the correct item is ranked #1 · MRR = mean reciprocal rank of the first relevant hit. Higher is better. The semantic subset (paraphrase, no word overlap) is the part that actually stresses meaning; the lexical subset is keyword-in-disguise.

What the numbers mean

  • BM25 collapses on paraphrase — P@1 of 0.067 (finds the right item ~1 in 15 times) when the user doesn't reuse the item's vocabulary. This is expected and matches the earlier blog analysis.
  • Jev can't recover it. Jev re-ranks the BM25 top-50 shortlist, so its ceiling is BM25's recall. On paraphrase queries the correct item is almost never in that shortlist, so Jev moves P@1 from 0.067 → 0.089 (roughly one extra query out of 45). The re-ranker is good; the candidate generator is the bottleneck.
  • Embeddings win because they do full-corpus dense retrieval. Vector-only computes cosine over all 136 items, so it finds paraphrases with zero word overlap — P@1 0.778, ~9× Jev.
  • Jev slightly hurts keyword queries. On the lexical subset it scores 0.818 vs BM25's 0.909 — re-ranking occasionally demotes a correct BM25 #1.
  • Latency & privacy regressions. Jev adds a ~259 ms network round-trip per query (embeddings are ~1–8 ms, fully local) and sends query + clip contents to TypeSafe.

Conclusion

Replacing embeddings with Jev re-ranking regresses semantic search dramatically, because re-ranking needs a high-recall candidate generator and BM25 alone has ~7% recall on paraphrase queries. The viable path to Jev is on top of embeddings — use embeddings (or another dense retriever) to build the shortlist, then let Jev re-rank it — not instead of them.

Methodology & caveats

The blog's original paraphrase set (20/80 lex/sem split) was never committed to the repo, so this run reconstructs a paraphrase-heavy set against the same 136 synthetic items: 11 keyword queries (reuse an item word) + 45 paraphrase queries (no shared stems), hand-labeled for the lex/sem split. Embedding numbers were produced by the pre-refactor eval at 72f8c6a (fastembed BGE-small-en-v1.5); Jev numbers by the current eval (jev-latest, single batched request per query). Both share the identical item set and query set, so the comparison is apples-to-apples.
